# Case 6: 10GB 大规模压力测试

## 测试目标

构建一个总对象量约 **10GB** 的大规模场景（~5GB 持久存活 + ~5GB 临时翻搅），测试 GC 在以下方面的表现：

- **大堆管理**：GC 在 10GB+ 堆上的标记/清扫效率
- **标记阶段耗时**：~5GB 存活对象的并发标记时间
- **Sweep 吞吐**：~5GB 死亡对象的清扫速度
- **RSS 峰值控制**：物理内存峰值是否接近活跃集合大小
- **堆增长策略**：大堆下 GC 触发阈值的合理性
- **碎片化**：长时间大量分配/释放后的 Region 碎片率

## 模型设计

1. **存活集合**（~5GB）：大量 LargeObject + 树 + 链表，持久引用
2. **临时翻搅**（~5GB 总计）：10 轮，每轮约 500MB 临时对象
3. **访问/创建均衡**：每轮先访问存活集合，再创建临时对象

## 内存估算

- 存活大对象：300 × ~16MB = ~4.8GB
- 存活树 + 链表：~200MB
- 每轮临时：~500MB（大对象 + 树 + 链表）
- 总分配量：~10GB（5GB 存活 + 500MB × 10 轮临时）
- 峰值活跃：~5.5GB

## 运行方式

```bash
source /path/to/cangjie/envsetup.sh
cjc benchmark.cj -o benchmark
MRT_REPORT=./runtime.log cjHeapSize=12gb ./benchmark
```

> 注意：需要 12GB+ 堆空间和充足物理内存，运行时间较长。
