# Case 3: 半存活半临时对象模型 (~500MB)

## 测试目标

构建一个**长期存活对象**与**短命临时对象**各占约 500MB 的场景，测试 GC 在以下方面的表现：

- **存活率 50%**：GC 需要标记约 500MB 的存活对象，同时回收约 500MB 的垃圾
- **标记效率**：大量存活对象对并发标记阶段的影响
- **Sweep 效率**：大量死亡对象的清扫速度
- **RSS 稳定性**：在稳定的存活/死亡比例下，物理内存是否锯齿稳定
- **堆碎片**：反复分配释放 500MB 后 Region 碎片化程度

## 模型设计

1. **存活集合**（~500MB）：分配约 500MB 的 LargeObject，持久引用不释放
2. **临时翻搅**（~500MB/轮）：每轮分配约 500MB 临时对象（树 + 链表 + 数组），轮结束即死亡
3. **翻搅轮数**：10 轮，每轮创建约 500MB 临时对象

## 内存估算

- 存活集合：约 500MB（~60 个 LargeObject，每个 ~8MB = 1048576 × Int64）
- 每轮临时：约 500MB（树 + 链表 + 数组组合）
- 总分配量：~5.5GB（存活 500MB + 临时 500MB × 10 轮）
- 峰值活跃：~1GB（存活 500MB + 当前轮临时 500MB）

## 运行方式

```bash
source /path/to/cangjie/envsetup.sh
cjc benchmark.cj -o benchmark
MRT_REPORT=./runtime.log cjHeapSize=2gb ./benchmark
```
