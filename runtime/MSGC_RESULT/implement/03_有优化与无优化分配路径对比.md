# MSGC 有优化与无优化分配路径全对比

## 概述

本文对比三种分配路径：
1. **无编译器优化**（SDK3 CopyGC / 或关闭 fast path）：直接走 runtime call
2. **CopyGC 风格 fast path**（SDK2 MSGC / 或动态大小对象）：inline 7条指令 TLAB bump pointer，但在 MSGC 下**永远 miss**
3. **MSGC size-class 特化 fast path**（SDK1 MSGC，编译期已知大小）：inline ~60条指令 bitmap 分配

---

## 一、路径一：无 fast path（直接 runtime call）

### 适用场景
- `EnableGCFastPath = false`
- 分配大小 > 16KB（大对象）
- JIT 模式（`CangjieJIT = true`）

### 调用链

```
cjc 生成的调用点
  └─ bl _CJ_MCC_NewObject          ; 直接调用 stub
        └─ CalleeSavedStub（汇编）  ; 保存 callee-saved 寄存器
              └─ MCC_NewObject（C++）
                    └─ HeapManager::Allocate(size, allocType)
                          └─ RegionSpaceMS::Allocate(size, allocType, local)
                                └─ AllocBufferMS::Allocate(size, local)
                                      ├─ SizeToClass(size) → cls
                                      ├─ FastAlloc(cls)
                                      │    ├─ AllocBump() or AllocFromBitmapFast()
                                      │    └─ hit → 返回地址
                                      └─ miss → SlowAlloc(cls)
```

### 汇编特征（binary 中无 fast path inline）

```asm
; 函数中直接调用 stub（无 inline fast path 代码）
bl _CJ_MCC_NewObject
```

### 性能特点
- 每次分配：函数调用开销（prologue/epilogue + callee-saved register 保存/恢复）
- 但 `AllocBufferMS::Allocate` 内部 FastAlloc 命中时约 15 条指令
- 总体 critical path：~30-50 条指令

---

## 二、路径二：CopyGC TLAB 风格 fast path（SDK2 / 无 MSGC 特化时）

### 适用场景
- `EnableGCFastPath = true`
- 分配大小为动态值（无法确定编译期 size class），或被 SDK2（dev260505）编译
- 对应 wrapper 函数：`CJ_MCC_NewObjectFast`（无 `cj-msgc-sizeclass` 属性）

### TLS 内存访问布局

```
x28 → ThreadLocalData
  +0x00: AllocBuffer* buffer
              │
              └─（MSGC 下强转存的是 AllocBufferMS*）
                     +0x00: RegionInfo* tlRegion_   ← 永远 = NullRegion()
                                 │
                                 └─ NullRegion::allocPtr = 0
                                    NullRegion::regionEnd = 0
```

### 内联汇编（约 7 条指令）

```asm
; === CopyGC TLAB fast path ===
ldr  x2, [x28]       ; TLS[0x00]: AllocBuffer* buffer
                     ;   MSGC 下实际是 AllocBufferMS*（强转）
ldr  x2, [x2]        ; buffer[0]: RegionInfo* tlRegion
                     ;   MSGC 下 = NullRegion()（tlRegion_ 字段）
ldr  x3, [x2]        ; tlRegion[0]: allocPtr (cur)
                     ;   NullRegion::allocPtr = 0
ldr  x4, [x2, #0x8]  ; tlRegion[8]: regionEnd (end)
                     ;   NullRegion::regionEnd = 0
add  x5, x3, x1      ; new_ptr = 0 + size = size（> 0）
cmp  x5, x4          ; size > 0 → 永远为 true
b.gt slow_path        ; 永远跳转 → 100% miss rate

slow_path:
bl   _CJ_MCC_NewObject  ; 回落到 runtime slow path（同路径一）

finish:
```

### MSGC 下的执行结果

| 步骤 | 值 | 说明 |
|------|----|----|
| `buffer` | `AllocBufferMS*`（强转） | MSGC runtime 将 msBuffer 存入 `buffer` 字段 |
| `tlRegion_`（buffer[0]） | `NullRegion()` | AllocBufferMS 第一个字段永远是 NullRegion |
| `allocPtr`（tlRegion[0]） | `0` | NullRegion 初始化 allocPtr = 0 |
| `regionEnd`（tlRegion[8]） | `0` | NullRegion 初始化 regionEnd = 0 |
| `size > 0`（cmp x5, x4） | 永远为 true | 任何 > 0B 的分配都 miss |
| **结果** | **永远 fallback** | 7 条指令只是白白消耗，100% fallback 到 runtime |

### 实际分配路径（fast path miss 后）

```
7条 inline 指令（全部白白执行）
  └─ bl _CJ_MCC_NewObject
        └─ CalleeSavedStub
              └─ MCC_NewObject
                    └─ AllocBufferMS::Allocate
                          └─ FastAlloc / SlowAlloc
```

### 性能特点
- **7 条 inline 指令是无效开销**，浪费 cache line（但量小）
- 实际路径与"无 fast path"几乎相同，总开销仅多出约 7 条无用指令
- 由于路径固定（永远 miss），分支预测器会快速学会"永远跳 slow_path"，实际惩罚约 0-1 cycle

## 三、路径三：MSGC size-class 特化 fast path（SDK1）

### 适用场景
- `EnableGCFastPath = true`
- 分配大小为编译期常量且 <= 16KB（常见于 struct/class 小对象）
- 对应 wrapper 函数：`CJ_MCC_NewObjectFast_MSGC_cls{N}_sz{S}`（有 `cj-msgc-sizeclass` 属性）

### TLS 内存访问布局

```
x28 → ThreadLocalData
  +0x4e: uint8_t encodedGCPhase  ← 第一步检查
  +0x58: AllocBufferMS* msAllocBuffer ← 第二步获取

msAllocBuffer →
  [offset_activeRegions + cls*8]: MSRegionInfo* activeRegions_[cls]
  
activeRegion →
  +0x00: uintptr_t allocPtr      ← BUMP 路径
  +0x08: uintptr_t regionEnd     ← BUMP 路径
  +[regionType_offset]: MSRegionType  ← 类型判断
  +[freeSlotCount_offset]: uint16_t
  +[allocBitmap_offset]: uint64_t*
  +[reservedBitmap_offset]: uint64_t*  ← PARTIAL bitmap CTZ
```

### 内联汇编（约 60 条指令，展开版）

```asm
; ============================================================
; 阶段 1：GC phase 检查（约 6 条指令）
; ============================================================
ldrb w9, [x28, #0x4e]           ; encodedGCPhase
subs wzr, w9, #PHASE_IDLE        ; == IDLE?
b.eq fast_path                   ; IDLE → 可以 fast alloc
subs wzr, w9, #PHASE_SWEEP       ; == SWEEP?
b.ne slow_path                   ; 非 IDLE 且非 SWEEP → STW/TRACE 阶段，走 slow path
                                 ; SWEEP 阶段也允许 fast alloc

fast_path:
; ============================================================
; 阶段 2：获取 msAllocBuffer 和 activeRegion（约 6 条指令）
; ============================================================
ldr  x9, [x28, #0x58]           ; msAllocBuffer
cbz  x9, slow_path               ; null → slow path

ldr  x10, [x9, #activeRegions_offset + cls*8]   ; activeRegion[cls]
cbz  x10, slow_path              ; 无活跃 Region → slow path

movz x15, #SlotSize              ; 编译期常量（如 32）

; ============================================================
; 阶段 3：判断 Region 类型（约 5 条指令）
; ============================================================
ldrb w11, [x10, #regionType_offset]
subs wzr, w11, #MS_REGION_BUMP
b.eq bump_path                   ; BUMP → bump pointer 分配
subs wzr, w11, #MS_REGION_PARTIAL
b.ne slow_path                   ; 不是 BUMP 也不是 PARTIAL → slow path

; ============================================================
; 阶段 4a：PARTIAL 路径 — bitmap CTZ 分配（约 25 条指令）
; ============================================================
partial_retry:
ldr  x12, [x10, #reservedBitmap_offset]   ; 64-bit reserved bitmap word
cbz  x12, slow_path
rbit x13, x12                    ; 反转位序
clz  x13, x13                    ; slot index = CLZ(RBIT) = 最低位 1 的位置

ldr  x14, [x10, #allocBitmap_offset]      ; allocBitmap base ptr
add  x14, x14, x13, lsl #3      ; 目标 bitmap word = base + index*8

ldr  x16, [x14]                  ; 读该 bitmap word
cbz  x16, partial_repair         ; bitmap word 为 0 → 需要修复

rbit x17, x16
clz  x17, x17                    ; bit index in bitmap word

movz x11, #1
lsl  x11, x11, x17
bic  x16, x16, x11               ; 清 bit（标记已分配）
str  x16, [x14]                  ; 写回 allocBitmap

ldrh w11, [x10, #freeSlotCount_offset]
sub  w11, w11, #1
strh w11, [x10, #freeSlotCount_offset]   ; freeSlotCount--

; 计算对象地址：regionBase + (word_idx*64 + bit_idx) * slotSize
; ... （省略几条地址计算指令）
str  x0, [obj_addr]              ; 写 typeinfo
mov  x0, obj_addr                ; 返回对象地址
b    finish

partial_repair:
; reservedBitmap 与 allocBitmap 不一致，修复后重试
bic  x12, x12, x11
str  x12, [x10, #reservedBitmap_offset]
b    partial_retry

; ============================================================
; 阶段 4b：BUMP 路径（约 12 条指令）
; ============================================================
bump_path:
ldr  x12, [x10]                  ; allocPtr
ldr  x14, [x10, #0x8]            ; regionEnd
add  x13, x12, x15               ; new_ptr = allocPtr + slotSize
cmp  x13, x14
b.gt slow_path                   ; 超出 → slow path

str  x0, [x12]                   ; *allocPtr = typeinfo
str  x13, [x10]                  ; region->allocPtr = new_ptr

ldrh w11, [x10, #freeSlotCount_offset]
sub  w11, w11, #1
strh w11, [x10, #freeSlotCount_offset]

mov  x0, x12                     ; 返回对象地址
b    finish

; ============================================================
slow_path:
bl   _CJ_MCC_NewObject

finish:
```

### 执行场景与命中条件

| 场景 | 是否走 fast path |
|------|----------------|
| GC 空闲（IDLE），activeRegion 存在，BUMP Region 未满 | ✅ BUMP 路径（~12条指令到达 finish） |
| GC 空闲，activeRegion 存在，PARTIAL Region 有空闲 slot | ✅ Bitmap CTZ 路径（~25条指令） |
| GC SWEEP 阶段 | ✅ 允许（同 IDLE） |
| GC TRACE / STW 阶段 | ❌ 直接 slow path |
| activeRegion 为 null（刚 flush）| ❌ slow path |
| activeRegion 为 FULL | ❌ slow path（SlowAlloc 换 Region） |
| 分配大小为动态值 | ❌ 不生成此路径，走 CopyGC 路径 |
| 分配大小 > 16KB | ❌ 不生成此路径，直接调 MCC_NewObject |

## 四、三条路径对比汇总

| 维度 | 路径一（无 fast path） | 路径二（CopyGC 风格，MSGC 下永远 miss） | 路径三（MSGC 特化 fast path） |
|------|----------------------|---------------------------------------|------------------------------|
| **适用 SDK** | 任意（关闭开关时） | SDK2 / 动态大小对象 | SDK1 / 编译期已知小对象 |
| **编译期工作** | 无 | 替换为 CJ_MCC_NewObjectFast | 替换为 CJ_MCC_NewObjectFast_MSGC_cls{N}_sz{S} |
| **inline 指令数** | 0 | 7 条（均无效） | ~60 条 |
| **MSGC 下 fast path 命中率** | N/A | **0%（永远 miss）** | **高（IDLE/SWEEP + Region 可用时）** |
| **fast path 命中时指令数** | N/A | N/A | BUMP: ~12条；PARTIAL: ~25条 |
| **miss 后路径** | 直接 runtime | runtime（同路径一） | runtime（同路径一） |
| **GC 阶段限制** | 无 | 无（直接走 runtime） | TRACE/STW 阶段直接 slow path |
| **实测性能（case1 -O2）** | — | 725ms（SDK2） | 967ms（SDK1） |

---

## 五、为什么 SDK2（永远 miss 的路径二）反而比 SDK1（路径三）快？

case1 benchmark 中 SDK2 总耗时 725ms，SDK1 总耗时 967ms。根本原因：

1. **case1 以小对象批量分配为主**（buildTree，每 node 24B → class 3 = 32B）
   - 路径三的 bitmap 路径虽然 fast path 命中，但每次需要约 25 条指令（PARTIAL）或 12 条（BUMP）
   - 路径二全部回落 runtime，runtime 的 FastAlloc 是 C++ 实现的同款 bitmap/bump，**不经过寄存器保存/恢复的 CalleeSavedStub**（stub 只保存 callee-saved 寄存器，对高频调用有额外开销）

2. **instruction cache 效率**：路径三的 60 条 inline 指令在每个 NewObject 调用点都存在，代码膨胀严重，造成 icache 压力

3. **分支预测**：路径二的 7 条指令模式固定（永远 miss），分支预测器快速学习，实际额外代价 < 1 cycle

4. **P2（大对象）和 P4（长存活扰动）差距最大**：这两个场景本身就无法命中 fast path（大对象 or GC 频繁），而 SDK1 的 60 条指令仍然存在但无用，icache 占用更多

5. **SDK1 有优势的场景**：P5（碎片化）略快（31ms vs 36ms），因为 bitmap 分配对碎片化内存的重用更高效，但差距极小

## 六、MSGC 完整分配路径（SDK1 fast path 命中时）

```
cjc 生成调用点（CJ_MCC_NewObjectFast_MSGC_cls3_sz32）
  │
  ├─ [GC phase check]: ldrb w9, [x28, #0x4e]
  │      IDLE/SWEEP → continue
  │      TRACE/STW  → bl _CJ_MCC_NewObject → CalleeSavedStub → ...
  │
  ├─ [get msAllocBuffer]: ldr x9, [x28, #0x58]
  │      null → bl _CJ_MCC_NewObject → ...
  │
  ├─ [get activeRegion[3]]: ldr x10, [x9, #offset+3*8]
  │      null → bl _CJ_MCC_NewObject → ...
  │
  ├─ [region type?]
  │      BUMP   → ldr allocPtr, cmp, str typeinfo, update allocPtr, return
  │      PARTIAL → rbit/clz bitmap, bic bit, str, return
  │      other  → bl _CJ_MCC_NewObject → ...
  │
  └─ [hit] return obj_addr（typeinfo 已写入）
     [miss] bl _CJ_MCC_NewObject
               └─ CalleeSavedStub（保存 callee-saved 寄存器）
                     └─ MCC_NewObject
                           └─ HeapManager::Allocate
                                 └─ RegionSpaceMS::Allocate
                                       └─ AllocBufferMS::Allocate(size, local)
                                             ├─ SizeToClass(size) = 3
                                             ├─ FastAlloc(3)
                                             │    ├─ AllocBump() or AllocFromBitmapFast()
                                             │    └─ hit → 返回地址
                                             └─ miss → SlowAlloc(3)
                                                   ├─ TakeCachedRegion(3) or RefillFromCentral(3)
                                                   └─ 在新 Region 上重试
```
